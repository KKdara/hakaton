# Юридический ассистент

Рабочий кабинет для поиска по нормативным и внутренним документам из кейса ПСБ. Вопрос, найденные положения и полный текст источника доступны в одном окне. Интерфейс написан на HTML/CSS/JavaScript; сервер на FastAPI подключает существующий модуль `retrieval`.

## Быстрый запуск

Нужен Docker Desktop с включённым движком и Docker Compose **2.24 или новее**. Из корня репозитория:

```bash
docker compose up --build
```

Открыть **http://localhost:8000**. Документация API: **http://localhost:8000/docs**. Порт 8000 опубликован только на локальном компьютере. Остановка: `docker compose down`.

Без `.env` и API-ключей работает локальный поиск по настоящей базе `data/knowledge-base.zip`. Это не демонстрационные ответы: сервер разбирает документы существующим парсером, нарезает их на фрагменты и ранжирует по словам. При первом запуске Docker скачает образ и зависимости; для самого локального поиска доступ в интернет не нужен. Шрифт также хранится в проекте.

## Что доступно в интерфейсе

- Чат с примерами вопросов и отдельными диалогами в пределах открытой вкладки.
- Поиск по всей базе или выбранному документу.
- Дословные выдержки со ссылками на статьи и пункты, раскрытие длинных фрагментов.
- Панель источников и просмотр полного текста с выделением выбранного фрагмента.
- Каталог документов с поиском по названию и отметками архивных редакций.
- Скачивание текста документа и копирование результата вместе с источниками.
- Отдельные состояния недостатка данных, загрузки и ошибки подключения; возврат вопроса для повторной отправки.
- Адаптивная вёрстка, клавиатурная навигация, отправка через Enter, новая строка через Shift + Enter.

**Граница текущей реализации:** веб-интерфейс подключён к поиску и оценке релевантности. Модуль генерации команды `answer.py` и платформенный скрипт `solution.py` работают отдельно и пока не подключены к веб-обёртке. Веб-обёртка показывает найденные основания, а не выдаёт их за проверенное заключение LLM. Она не вызывает DeepSeek и не заменяет будущие модули генерации и самопроверки команды. В результатах показаны дословные выдержки и ссылки на источники.

## Архитектура

```text
Браузер: web/static/
    │ POST /api/chat
    ▼
FastAPI: web/app.py
    │ валидация запроса, обработка ошибок
    ▼
Адаптер: web/service.py
    ├─ local → parser.py → chunking.py → ранжирование BM25
    │             └─ data/knowledge-base.zip
    └─ vector → retrieval.retrieve()
                  ├─ BAAI/bge-m3 через OpenAI-совместимый API
                  ├─ data/chroma_db (Chroma, cosine)
                  ├─ необязательный Qwen3-Reranker-8B
                  └─ sufficient / partial / insufficient + фрагменты
    │
    ▼
Выдержки + ссылки + предупреждения → чат и панель источников
```

Каталог и просмотр документов используют исходный ZIP и тот же парсер, что и подготовка индекса. ZIP не распаковывается в файловую систему. Документ выбирается по идентификатору из базы, произвольные пути сервер не открывает. Текст запроса и документов вставляется в DOM как текст, без выполнения HTML. Диалоги хранятся в памяти вкладки и исчезают после обновления страницы; сервер не хранит историю. Каждый вопрос обрабатывается самостоятельно, без семантического контекста предыдущих реплик.

`web/service.py:search()` — точка подключения дальнейшего пайплайна команды. Контракт результата: `answer`, `status`, `reason`, `sources`, `warnings`, `mode`. Для замены выдержек на сгенерированный ответ нужно подключить модуль генерации к найденным источникам и проверять юридически значимые утверждения до возврата результата. Используемую модель и её подключение следует документировать после интеграции; в кейсе указана DeepSeek V4.1 Flash.

## Зависимости и локальный запуск

Python **3.12**. Node.js и сборщик фронтенда не требуются.

| Файл | Назначение |
| --- | --- |
| `requirements-web.txt` | FastAPI 0.115.12, Uvicorn 0.34.2, python-dotenv 1.1.0, HTTPX 0.28.1 |
| `requirements.txt` | Chroma 1.5.0 и OpenAI SDK 1.76.0 для векторного режима |
| `requirements-retrieval.txt` | Зависимости поиска и pytest 8.3.5 |

Только интерфейс и локальный поиск:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux / macOS:
# source .venv/bin/activate
pip install -r requirements-web.txt
python -m uvicorn web.app:app --host 127.0.0.1 --port 8000
```

Для векторного режима дополнительно: `pip install -r requirements.txt`. Docker устанавливает оба набора.

## Настройки

Скопировать `.env.example` в `.env` в корне проекта. Действующие ключи в репозиторий не добавлять. Сервер читает `.env` при старте, Docker Compose передаёт его в контейнер.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `SEARCH_MODE` | `auto` | `auto`: vector при наличии URL и ключа, иначе local; также можно явно выбрать `local` / `vector` |
| `LLM_BASE_URL` | пусто | Базовый URL OpenAI-совместимого сервиса эмбеддингов, предоставленный организаторами, включая путь API при необходимости |
| `LLM_API_KEY` | пусто | Ключ этого сервиса; используется только на сервере |
| `EMB_MODEL` | `BAAI/bge-m3` | Модель эмбеддингов запросов, должна совпадать с моделью индекса |
| `CHROMA_DIR` | `data/chroma_db` | Путь к векторному индексу относительно рабочей директории |
| `CHROMA_COLLECTION` | `legal_docs` | Коллекция Chroma |
| `RETRIEVAL_TOP_K` / `RETRIEVAL_CANDIDATES` | `6` / `30` | Число результатов и кандидатов в vector |
| `RETRIEVAL_EXCLUDE_OUTDATED` | `true` | Исключение утративших силу документов в vector; в local они исключены всегда |
| `RERANK_ENABLED` | `false` | Включить реранкер в vector |
| `RERANK_MODEL` | `Qwen/Qwen3-Reranker-8B` | Модель реранкера |
| `RERANK_BASE_URL` / `RERANK_API_KEY` | из `LLM_*` | Сервис с маршрутом `POST /rerank` и ключ |
| `RERANK_TIMEOUT` | `60` | Таймаут реранкера, секунды |
| `RERANK_CANDIDATES` | `20` | Кандидаты на реранкинг |
| `VEC_HIGH` / `VEC_LOW` | `0.45` / `0.30` | Начальные пороги релевантности vector |
| `RERANK_HIGH` / `RERANK_LOW` | `0.70` / `0.30` | Начальные пороги после реранкинга |
| `KNOWLEDGE_ZIP` | `data/knowledge-base.zip` в корне проекта | Альтернативная база для каталога и local |

Поддерживаются также `OPENAI_BASE_URL` / `OPENAI_API_KEY` вместо `LLM_*`. Имя конкретного сервиса и рабочий URL нужно взять из технического регламента организаторов: в PDF кейса адрес и ключ не приведены. Внешний поиск в интернете для ответов не используется. В vector текст вопроса передаётся сервису эмбеддингов; при включённом реранкере ему также передаются фрагменты базы.

### Подготовка векторного индекса

При наличии доступа к API из корня репозитория:

```bash
python build_index.py
python build_embeddings.py
python build_vector_store.py
```

Перед этими командами экспортировать `LLM_BASE_URL` и `LLM_API_KEY` в окружение оболочки: старые скрипты подготовки сами `.env` не читают. Без ключей `build_embeddings.py` создаёт нулевые заглушки — они **непригодны для семантического поиска**. Не считайте существующий индекс проверенным, пока не убедитесь в происхождении его векторов. `build_vector_store.py` пересоздаёт коллекцию `legal_docs`, поэтому перед пересборкой сохраните нужный индекс. Модель эмбеддингов должна быть одинаковой при индексации и поиске. При изменении ZIP пересоберите индекс и перезапустите сервер.

## API

| Метод и маршрут | Результат |
| --- | --- |
| `GET /api/health` | Состояние чтения базы, режим, число документов и фрагментов; не проверяет удалённый API |
| `GET /api/documents` | Каталог и метаданные |
| `GET /api/document?doc_id=…` | Полный текст выбранного документа |
| `GET /api/document/download?doc_id=…` | TXT с текстом после обработки парсером |
| `POST /api/chat` | Поиск, оценка достаточности и источники |

Тело запроса к чату:

```json
{
  "message": "Какой испытательный срок предусмотрен при приеме на работу?",
  "doc_id": null,
  "event_date": null
}
```

`event_date` принимает `YYYY-MM-DD`. Вопрос — до 4000 символов. Пустой запрос возвращает 422, отсутствующий документ — 404, ошибка поиска — 503 с понятным сообщением без вывода ключей в браузер. Полная схема доступна в `/docs`.

## Порядок проверки

1. Запустить проект и открыть `http://localhost:8000`. В панели справа должно быть **21 документ / 230 фрагментов** для базы из репозитория.
2. Выбрать пример про испытательный срок. В результатах должна появиться статья 70, в правой панели — ссылки на источники.
3. Открыть ссылку `[1]`: проверить выделение дословного фрагмента в полном тексте, скачать TXT. Закрыть документ клавишей Escape.
4. Выбрать конкретный документ в фильтре и задать вопрос: источники должны относиться только к нему.
5. Отправить «рецепт борща со сметаной»: ожидается сообщение о недостатке данных, без выдуманных норм и ссылок.
6. Указать дату события: результат должен предупредить, что редакцию нужно проверить вручную.
7. Открыть «Документы», найти документ по названию и проверить отметку утратившего силу регламента. В поисковые результаты local архивный регламент не попадает.
8. Проверить новый диалог, возврат к диалогу из боковой панели и мобильную ширину.

Автоматические проверки веб-обёртки без внешних сервисов:

```bash
pip install pytest==8.3.5
python -m pytest tests/test_web.py -q
```

Существующие проверки retrieval: установить `requirements-retrieval.txt` и выполнить `python -m pytest tests/test_retrieval.py -q`.

## Известные ограничения

- Веб-обёртка пока не вызывает генератор `answer.py` и не использует платформенный сценарий `solution.py`. Автоматическая самопроверка юридических утверждений в веб-интерфейсе не реализована.
- Дата события служит контекстной отметкой. Автоматическое сопоставление редакций и дополнительных соглашений по дате не реализовано. Фильтр актуальности использует метаданные существующего парсера, а не самостоятельную правовую проверку.
- Local использует BM25 с простым сопоставлением префиксов слов, без полноценной морфологии и понимания вопроса. Найденные результаты всегда `partial`, даже при высоком совпадении. Непрофильный запрос может дать совпадение по отдельным словам; это не подтверждает возможность юридического ответа.
- Статус `sufficient` в vector означает достаточность по порогам retrieval, а не проверку полноты юридического вывода. Начальные пороги требуют калибровки.
- Недоступность vector не подменяется молча локальными результатами: пользователь видит ошибку и может повторить запрос.
- Нет авторизации, постоянного хранения диалогов, загрузки пользовательских документов и серверного ограничения частоты запросов. Конфигурация предназначена для локальной демонстрации с тестовыми данными. Для сетевого развёртывания потребуются инфраструктура доступа и ограничения нагрузки.

## Структура проекта

```text
web/app.py            HTTP API и раздача интерфейса
web/service.py        адаптер retrieval и локальный поиск
web/static/           интерфейс и локальные шрифты
retrieval/            существующий векторный поиск и оценка релевантности
answer.py             модуль генерации команды (отдельно от веб-интерфейса)
solution.py           платформенный сценарий команды
parser.py             существующий парсер документов
chunking.py           существующая структурная нарезка
build_*.py            подготовка чанков, эмбеддингов и Chroma
data/                 предоставленная база и индекс
tests/                проверки retrieval и веб-обёртки
Dockerfile            контейнер Python 3.12
compose.yaml          запуск одной командой
.env.example          настройки без секретов
```
